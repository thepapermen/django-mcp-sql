{% extends "oauth2_provider/base.html" %} {% load i18n %} {% comment %} Package default consent page. Layout-agnostic (extends DOT's bundled base); consumers re-theme by overriding `mcp_sql/authorize.html` in their own template dir. Three values, all injected by `MCPAuthorizationView.render_to_response`: `resource_name` names what is being accessed (this MCP server); `client_label` names who is asking, and is present ONLY for clients whose name the operator configured — a self-registered client sends its own `client_name`, so showing that would let anyone label themselves; and `client_destination` is where the authorization code will be delivered, which oauthlib has already validated. It names a provider or a machine, not whose account there: a shared provider callback (Claude.ai, every ChatGPT connector) renders identically for an attacker's own connector. DOT's stock template shows `application.name`, which for a self-registered client is the opaque `mcp-sql-` and for everyone else says nothing about the destination. Approving this form is an explicit, CSRF-protected POST, so a phished authorization link cannot complete silently; the check the user can actually make is the "Only continue if you started this from there" instruction. Keep both it and the destination visible in any re-theme. {% endcomment %} {% block content %}
